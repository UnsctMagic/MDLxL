# MDLxL project map

Use the row matching the user's feature or symptom, then search within those
owners. This is a navigation guide, not a required reading list. Paths and named
symbols were checked against the source during the context setup; always check
the current branch before using them. Historical evidence is not a fresh test result.

## Start and route

[package.json](../package.json) starts [electron/main.cjs](../electron/main.cjs);
[preload.cjs](../electron/preload.cjs) exposes desktop operations.
[index.html](../index.html) loads [app/main.jsx](../app/main.jsx), which mounts
[App.jsx](../app/App.jsx). UI routing is split across
[AppToolbar.jsx](../app/AppToolbar.jsx), [AppSidebar.jsx](../app/AppSidebar.jsx),
[AppPanels.jsx](../app/AppPanels.jsx) and [AppDialogs.jsx](../app/AppDialogs.jsx).
Search the relevant component or dialog type before reading all of App.
App's small state owners are [usePreferences.js](../app/usePreferences.js)
(preferences, first-paint cache, settings tab and saves),
[PreferencesContext.jsx](../app/PreferencesContext.jsx) (shared preferences and
`openHotkeySettings`; explicit GamePreview/Viewport preferences still override it),
[useEditorDisplay.js](../src/useEditorDisplay.js) (XL/VIS clean views and overlays,
including POSE's display), [view-menu.json](../src/view-menu.json) (one View/Quick Display list for both looks; [View/vertex task](agent-tasks/view-vertex-display.md)), and [usePortraitState.js](../app/usePortraitState.js)
(portrait controls, session resets and remembered backdrop look).
Shared shell pieces: the classic window and `LoadingWindow` in
[Dialog.jsx](../app/Dialog.jsx) (`onSubmit` gives an OK/Cancel form), the tool-window
shell in [ToolWindow.jsx](../app/ToolWindow.jsx) (resource editors, AnimXL, Particle
Editor, Sort My Mess, Attachemator, Auto Corpse; both emit `.mdlxl-overlay`/`.mdlxl-window`,
which `new-look.css` styles, and the backdrops use `--z-modal`/`--z-tool-window`/`--z-workspace-modal`
from `theme.css`), the shared fields in [Fields.jsx](../app/Fields.jsx) (`useDraftNumber`
for every typed number, `useRangeCommit` and `RangeField` for every slider and its one look
in `styles.css` `.range-field`, `Section`, `Check`), Tab trapping in [focus-trap.js](../app/focus-trap.js),
popover outside-click/Escape in [useDismiss.js](../app/useDismiss.js), and small
remembered choices in [local-store.js](../src/local-store.js) /
[useStoredState.js](../app/useStoredState.js) (never rename a stored key).

## Conventions

New IPC channels use `area:verbNoun` with a singular area; the preload key is `verbAreaNoun`.
New localStorage keys use `mdlxl-<feature>-<thing>`. Existing names stay as they are.

**Live drags** ([why and when not](ARCHITECTURE.md#only-do-work-someone-can-see)). A pointer reports far more often than the display refreshes. A `pointermove`
handler only records the latest point and calls `schedule()` on a `createFrameCoalescer`
([viewport-performance.js](../app/viewport-performance.js)); the drag math, 2D redraw, live
preview and any parent `on…Change`/`set…` call run in its callback, at most once per frame.
Pointer up calls `flush()` first, cancel calls `cancel()`. Live previews update only what the
drag changed. Add each new drag handler to [live-drag-frames](../test/live-drag-frames.test.js).

## Run the relevant verification

Run commands from the repository root with the existing dependencies available.
[README](../README.md#source-development) and [package.json](../package.json) own
setup and script definitions; [CI](../.github/workflows/ci.yml) owns the merge checks.

- `node --test test/animation.test.js test/animation-tracks.test.js` is an example
  of a focused source run; substitute the verified test files from the matching row.
- `pnpm test` / `pnpm run test:compatibility` cover `tests/*.test.js`;
  `pnpm run test:source` covers `test/*.test.js`. These are different suites.
- Build first with `pnpm run build` when checks need bundled runtime assets;
  fetch pinned FFmpeg with `pnpm run fetch-ffmpeg` when required. Follow CI's
  order for a full run and its existing known-failure comparison.
- `.electron.cjs` files are separate interaction harnesses, outside those test
  globs. Inspect the chosen harness's setup/profile/environment requirements before
  running it. Do not label a source-only pass as packaged mouse/UI verification.
- `pnpm run test:packaged [variant] [all|core|names]` runs those harnesses
  (`test/*.cjs`) unattended on a hidden Windows desktop, under GPU/no-GPU/slow-CPU/
  HiDPI variants, with each harness's env/fixtures in one table. See
  [packaged-app tests](PACKAGED-TESTS.md).
- New or touched tests use the shared helpers in `test/helpers/` (`launchApp`,
  `appTarget` from the one `MDLXL_TEST_EXE` variable, `fixturePath`, `tempDir`,
  model fixtures, approximate asserts); see
  [shared helper](PACKAGED-TESTS.md#shared-helper). Suppressed informational messages are read through
  `waitForInfo` / `infoMessageCursor` in that helper; see the
  [0.38 test repair lane](agent-tasks/release-038-test-repairs.md).

For continuation, locate the matching active note in [agent tasks](agent-tasks/README.md)
or the existing topic handoff. Only open historical notes when their evidence is needed.
