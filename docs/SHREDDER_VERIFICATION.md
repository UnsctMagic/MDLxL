# Shredder verification

Toggle the bird / **SHRD** button beside **KEY / VIS**. The existing **Settings → Mouse → Shredder** checkbox shows the same remembered preference. Shredder is off by default. No panel or sidebar width was added; the updater visitor and its sprites are unchanged.

The helper greets the user, advises after two uses of the same mouse control or four mixed shortcut-capable actions within 30 seconds, and offers occasional useful shortcuts while idle. It uses current effective bindings, including remaps and cleared assignments. Long leader sequences, conflicting assignments and uncomfortable one-hand reaches are excluded. The supplied `Z+1` / `Z+1+0` examples are covered by the reach check; no new shortcut syntax or bindings were introduced. Using a taught shortcut clears frustration and receives a short acknowledgement.

Continued editing clicks after a displayed tip cause a reminder after about two seconds. Seven ignored clicks, a displayed reminder and at least four seconds of continued activity cause a seven-second tantrum. This can happen only once per enabled session, followed by a quiet recovery; advice can continue afterwards. Ordinary mouse editing counts after advice was shown, so switching between tools no longer conceals that the user is ignoring him. Idle users are not accused of ignoring tips.

Only the bird's small hit area accepts pointer input. It supports real pointer-captured dragging, stays where dropped initially, and later resumes walking along editor edges and making flights outside the view. Hovering does not make him evade the cursor. Balloons remain click-through; visual cursor pecks temporarily disable the bird's hit area and cannot edit the model or move the mouse. All normal helper behavior preserves the model's serialized bytes.

Mordor uses a dedicated painterly animated **Morgoth Shredder** sheet: a large iron crown with three bright Silmarils is painted into each idle, walking, attack and wing-cycle pose. The former separate SVG crown is gone. [Art and generation prompts](../app/assets/shredder/README.md) document the built-in imagegen asset.

Mordor keeps flying, pecking, carrying and speaking varied Mordor lines. Attacks repeat roughly every 1.4 seconds while available, with larger visible vertex displacements; there is no small burst limit or 30-second rest. Clicking no longer cancels flights. Held editing gestures and text entry defer atomic commits. Visible vertices are selected through the live Vertices camera or the existing skinned Bones/Movement preview. Edits use the existing document, selection-history and undo path. Authored normals, UVs, topology, bindings, textures and other sections are retained; only vertex positions and bounds change. The attack scale is anchored to the starting geometry so repeated attacks do not exponentially inflate bounds and run out of visible targets.

Saving, read-only documents, modals, hidden windows and pending drafts prevent model edits. Model/view switches and disabling Shredder cancel pending plans. Committed attacks remain ordinary undoable edits and reach the model file only if the user saves. Paint, UV and Showcase have separate editing owners and are not geometry attack targets.

Both directions into Shredder + Mordor retain the exact English warnings, `Proceed?`, `Aye!` and `Nay!`. Nay leaves the attempted preference unchanged. Speech is translated into English, Russian, Spanish and Chinese or the program's Mordor cipher/font; shortcut keys and **SHRD** remain literal.
