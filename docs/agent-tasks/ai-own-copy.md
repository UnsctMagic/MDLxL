## Goal and completion criteria

Owner's agreed concept (30 Oct 2026, owner said go; do not reinterpret):

1. When a message is sent, the AI works on its OWN copy of the model plus the
   selection/view captured at send time. The user's clicks AND edits never stop
   it. Only real model edits count as changes; selection, checked geosets, active
   geoset, camera, sequence/frame never do.
2. Peek: while the AI works the user can view the AI's copy, view only. Peek has
   its own camera: it never stops the AI and never changes the AI's own view or
   pictures. Small toggle near the AI working indicator; no new permanent panel.
3. When the AI finishes:
   - No clash (user changed nothing, or only parts the AI did not touch): merge
     into the live model as ONE Undo step, no question.
   - Clash (both changed the same parts): friendly GREEN question with
     "Save as a new file", "Adapt to your changes" (the AI fits its changes onto
     the user's latest version, not a redo; editing again meanwhile brings the
     choice back) and "Compare side by side" (OptimizeXL-style previews, pick one).
4. A forced stop shows ONE short friendly green line; the AI never writes an
   essay. Stale-target text and AI instructions do not guess causes.

Done: source tests, packaged harness (geoset checks + unrelated edit auto-merge;
same-part edit shows the green question; Peek rotation leaves AI pictures alone),
PR into `main` with `Session:` line, `ready for review; awaiting merge approval`.

## Findings and decisions

- Verified (code, 0d5ffe01): the Magpie lock-out came from `checkAiTarget` comparing
  `aiSelectionSignature` (includes checked geosets) on on-screen non-region targets.
- Decision: the copy is a hidden editor session (`EditorDocument.restoreRecoveryState`
  of the live doc without history) held on the target (`target.copy`), not in the tab
  list. The target keeps `documentId` = the user's tab, so versions, chats, references,
  queues and "one job per model" keep their keys. Edits/Undo/selection go through the
  existing off-screen helpers (`editTab`/`undoTab`/`selectTab`); pictures through the
  hidden renderer with the copy's model. No recovery checkpoints are written for it.
- Decision: clash = the AI and the user changed the same part. A part is the item a
  change path belongs to (`/Geosets/2`, `/Bones/5`, `/Sequences/1`; one-level paths
  such as `/Info/Name` themselves). Adding/removing items of a list (a splice on the
  list itself) touches the whole list. Bounds/count fields in `Info` are derived and
  never clash; extents are recalculated for the AI's geosets on merge.
- Decision: editor commands (other than Undo/Redo), program controls and timeline key
  picking act on the user's model, so on a copy they are refused with a plain message
  pointing to scripts/patches (one way: the same tools as background birds).
- Decision: any end of the job (done, stopped, error) merges what the AI applied, as
  the old "applied edits remain in Undo" behaviour promised.
- Decision: "Compare side by side" picks either the AI result (AI wins on the clashing
  parts, the user's other edits stay; one Undo step) or the user's version (AI result
  dropped).
- Decision: read-only documents and external MCP calls keep the old live behaviour
  (only the chat's send creates a copy), but the stale-target text no longer guesses.
