# OptimizeXL

Open **OptimizeXL** from the existing optimizer toolbar button or command. It opens a separate editor window, using the same detached-window mechanism as UV. Changes reach the open model only when you choose **Save** (see below).

Future examples follow the [teaching agreement](OPTIMIZEXL_TEACHING.md): reusable rules, explicit correction ownership, no conflicting overlap and preserved accepted results.

Hive diagnostics are classified separately from optimizer proposals. Every checker finding keeps an explicit disposition: a supported preview, a route to the owning stage, or a manual-review explanation. **Unused data** also runs the checker and reports remaining unused notices; an empty list of removable objects does not mean the model is checker-clean. **Review Hive cleanup** opens the supported fixes, and the checker is rerun after approval.

## Review workflow

**Before** and **After** sit directly next to each other on the left, separated only by a one-pixel line; the controls are on the right. Before and its file size stay pinned to the model as it entered OptimizeXL. After shows the approved changes plus the current proposal. Approval never replaces the original on the left. The saving estimate compares that original with the current After. Both render surfaces align to physical screen pixels so fractional pane widths do not soften one side. Left-drag either viewport to rotate both; use the wheel to zoom both. OptimizeXL always uses wheel zoom regardless of the main editor's sensitivity-adjustment mode, without changing that saved setting. Pan, animation selection, scrubbing, playback and speed are also shared. Each adjustment is calculated from the last approved model, so lowering strength restores detail rather than simplifying an already simplified candidate.

**Speed (%)** accepts 0–200: 100 is normal speed, 200 is double speed and 0 holds the current pose. Both local and global animation follow that speed. Global sequences share an independent clock between the two views, completing their own cycles while the selected animation loops. Changing animations, scrubbing or rebuilding a candidate preserves their phase. Pause freezes both clocks; Loop off stops at the selected animation's final frame.

**Approve** keeps the current proposal. **Skip stage** advances without applying it. Repair stages also have **Skip fix** and **Next stage**. **Back** undoes the last approval or skipped stage. The stage buttons allow returning directly to a particular operation; leaving a stage discards its unapproved proposal.

Scroll over any dropdown to move directly to its next or previous option. Selecting another animation keeps playback running when it was already playing. In either repair stage, expand **Select fixes** for a checkbox beside each finding, plus **Select all** and **Clear all**. **Preview all selected fixes** combines the checked corrections in After. **Approve selected** keeps them together as one undoable step; unchecked fixes remain untouched. Changing checkboxes clears the proposal until you preview the new selection. Each correction retains its own Advanced settings.

A green star inside a stage button means a check found changes available to review. Unchecked stages do not show speculative stars. Background checks test real candidate reductions and available repairs; valid existing spheres need no star just because other presets exist. Approval or an explicit no-change review clears the star. Nuclear at zero strength and Unused with every option disabled use the availability check instead of pretending those settings tested the operation. Skipping does not count as approval. Changed accepted data or exclusions trigger fresh checks; Back restores the earlier review state. A failed availability check exposes its reason in the stage button's tooltip.

**Exclude geosets** appears in Duplicate data, Animation optimization, Unused data and Nuclear. It uses the Vertices editor's four-column geoset box, with checkboxes, Shift ranges and All/Clear/Invert. Checked geosets remain in both previews with their authored animation visibility and are excluded from reductions. The same exclusions persist across these stages; Back restores the exclusions used by an undone approval. Hover the list or either model to highlight the corresponding geoset in both previews, using Appearance's geoset highlight color, type and hover-source settings. The local Highlight Geoset switch starts on and does not change the main editor's preferences.

Excluded vertex records, faces, UVs, normals and matrix groups are not reduced. Animation reduction also preserves their bones and ancestors, geoset animation, materials and texture animations; shared dependencies stay intact even when another geoset uses them. Duplicate bone merging retains excluded rig dependencies. Exact resource/node cleanup may renumber references while preserving what they refer to. Exclusion does not redistribute Nuclear's reduction pressure onto other geosets: eligible geosets keep the same strength, so more exclusions usually mean less saving. Repair and collision-sphere stages are separate operations and do not display this reduction-only box.

Results appear beneath the saving estimate. **Changed animations** shows one line per animation, such as **5 changes to animation Attack - Slam**; click it to inspect the animation. Each removed key counts once, even when shared by several geosets. **Geosets to review** in Duplicate data lists only affected geosets; hover to highlight both previews using Appearance settings. **Data to remove** in Unused data names the removed materials, textures, bones/helpers and global sequences, plus unused vertices/bone groups by geoset. These use the current approved model's names and numbers. Closing animation details or leaving the stage restores the animation/frame you were viewing before inspection.

Selecting a repair finding temporarily jumps to its animation and frame. Approve or Skip immediately selects the next remaining finding. Leaving the stage, clearing the finding or reaching the end of the queue restores the animation and frame you were viewing beforehand. Camera angle, zoom, speed and loop settings stay unchanged. Switching between several findings retains the original return point. Browsing findings during a combined preview retains all checked corrections in After. **Back** reopens the undone finding or combined selection. Ordinary stage changes keep animations you selected manually.

**Simple** offers a fine strength slider for duplicate merging, animation reduction and polygon reduction. **Advanced** exposes the actual tolerances and protection options. Hover an option name for a plain-language explanation, or click its small information button to keep the explanation open. Escape or clicking elsewhere dismisses it. Zero strength performs exact cleanup in the first two stages; zero nuclear strength performs no polygon reduction. Unused-data removal is an exact operation, with individual categories in Advanced.

| Stage | What is proposed |
| --- | --- |
| Insanity FIxer | First stage: later reductions refuse models with broken references. Runs the bundled Hive checker, showing errors, severe findings, warnings and unused notices. **Fix everything** previews every automatic repair at once, checks again and repeats until nothing more can be fixed; **Approve all fixes** keeps the result. Single repairs can still be selected and reviewed. Besides bounds, static particle gravity, keys beyond global-sequence duration, opening keys and redundant keys, general checker repairs cover the checker's own list of findings: key order, negative and empty tracks, broken references, helpers that move vertices, bones without vertices, empty and oversized geosets, light attenuation, the Origin attachment point, overlapping or same-start animations, misspelt standard names, fading visibility and more (see `src/optimizexl-checker-repairs.js`). Repairs that need a decision (missing material or texture, loose vertices, blend modes, file types) show a **Choice** with a default. Findings with no repair stay listed for manual editing. |
| Duplicate data | Merge compatible complete vertex records (position, normal, every UV channel and bone bindings), duplicate matrix groups and equivalent leaf bones. A near match merges only when it is the same point saved twice: its gap must also be under 2% of the shortest edge touching either vertex, so breathing holes, visor slits and stacked layers inside one geoset stay. Separate geosets are never merged with each other. On solid or cut-out surfaces that do not fade, remove triangles that exactly repeat another triangle's corners (every attribute) with the same winding; blended, additive, modulated or fading surfaces keep repeats, since drawing twice is visible there. Opposite-winding two-sided faces and faces that only coincide after a tolerance merge stay. Advanced supplies position, UV and normal-angle tolerances. |
| Animation optimization | Default **Local tracks**: remove redundant local step, linear and curved (Hermite/Bezier) keys. Increasing strength permits sampled position, rotation and scale differences checked against the original curve, including points between keys. Motion protection returns authored keys where the result strays more than 10% of a component's own range or turning excursion, so a model-sized tolerance cannot flatten small speech or other cycles. A turn or scale change is also limited by the part's reach: the farthest vertex or child point it carries may not move more than the position tolerance, so a flail or long weapon keeps its swing while short joints still reduce. Keys come back one at a time at the worst point, not whole spans. First/last authored keys and retained spline controls stay. Global tracks and ambiguous overlapping sequences are retained; approximate quaternion reduction requires normalized controls. Advanced also offers **World-space bound**, described below; this does not change the default or its accepted results. |
| Unused data | Remove vertices unused by faces, unreferenced resources, unused bones/helpers and orphan global sequences. Ancestors of used nodes and references from effects and events remain. |
| Irregularities Fixer | Offer suspected visibility leaks, endpoint mismatches, repeated body jitter, brief position/rotation excursions, sudden yanks and scale distortion. Compare motion speeds with other animations and nearby movement. Selecting a finding previews a full replacement of the flagged motion between retained surrounding poses; Approve keeps it and Skip leaves it unchanged. |
| Sphereomancer | Choose or scroll through collision-sphere presets, scale the group, and edit/add/remove individual spheres in Advanced. Collision overlays appear only during this phase. |
| Nuclear Polygon Destroyer | Reduce triangles with a 0.01%-step strength slider and attribute-aware surface simplification. Advanced exposes target polygon count, shape/texture error budget, UV/boundary, sharp-edge and skinning protections. The displayed KB saving comes from the actual candidate MDX serialization. |

Irregularity proposals cover rare living-sequence appearances of portrait/corpse geometry, body parts reappearing in Decay Bone, Death → Decay Flesh, looping Stand/Walk/Portrait endpoints, shared combat endpoint poses, and separately rooted stationary parts during otherwise moving Dissipate sequences. These are review heuristics, not universal rules. Pose repair currently handles local linear and step TRS tracks; it preserves later authored decay keys. Advanced can reverse the reference endpoint for individual loop/death-to-decay proposals.

Motion correction replaces the detected excursion completely rather than reducing its strength. It can change a bad stored pose as well as faulty curve controls. Position and scale repairs act on the affected axes; rotation repairs interpolate orientations. Unaffected axes, channels, surrounding anchors, exterior curve handles and other animation intervals remain intact. Key times stay unchanged. Global tracks, stepped motion tracks and overlapping sequence intervals are not automatically repaired by this motion rule. Speed alone is not proof of a defect: the scan also looks for brief excursions, repeated reversals or evidence of copied position controls. These heuristics cannot identify every possible animation defect or reconstruct an unknown original motion; the two previews and approval remain the intent check.

Copied-control translation corruption can also leave a small one-way speed hitch without an extra reversal. Its repair requires uneven key timing, a substantial local rate change and an independently matching rate on an exterior segment. It restores the supported rate through the intermediate key. A small deviation alone is not sufficient evidence. Supplied good models are regression references; their names, tracks and key times are not embedded in the detector.

An additional **suspicious whole-body snap** finding catches repeated offsets from the same holding pose and brief outward excursions with copied-control evidence. A very fast out-and-back body move between long holds can also warrant review without copied controls. Body ownership is measured from skinned geometry, so a separate effect is not treated as whole-body motion. The proposal reconnects retained holding poses or removes the brief excursion. These optional findings supplement the existing rules; reduction settings and previous repair behavior stay unchanged. Checked curve and snap repairs can be previewed together against the same original evidence. Both supplied flail fixtures have saved output-hash regression baselines covering the accepted optimizations and repairs.

The motion context pass compares abrupt movement across the model's animations and measures how much visible geometry each bone affects. A similar repeated body pattern is **orange** for inspection. Erratic timing, size or direction across the body, or separate body parts jerking with unrelated timing, is **red**. Ordinary coordinated limb movement and repetition confined to a small mechanism do not create a new context warning by themselves. Color is an inspection priority, not proof of an error. The optimizer needs only the model being reviewed; supplied repaired examples are used in regression tests, never as a runtime counterpart.

Context annotates existing motion proposals without changing their corrections. A new contextual correction requires supported holding poses around the excursion. Otherwise the finding says **Inspect only**: selecting it seeks the suspect animation, but its checkbox and Approve are disabled. A sharp return can be a correct pose surrounded by damaged keys; flattening it would erase intended motion. **Select all** selects supported corrections only, and inspection-only findings do not create a green availability star. These findings remain available for inspection and skipping in the same compact controls.

For shared combat poses, the fixer compares the skinned rig at the first and last frames of Attack and Stand Ready sequences, plus only the first frame of Death. A strict majority of agreeing endpoint poses spanning at least two animations establishes the reference; Stand Ready has no automatic priority. One proposal corrects both ends of an outlying Attack/Stand Ready sequence together, or only Death's start. It names the agreeing animations, preserves interior keys and Death's final pose, and leaves independent effects/global animation untouched. Ambiguous groups, overlapping sequence intervals and differing spline channels do not produce this automatic proposal. Global animation may legitimately show a different phase at two timeline frames even after the local endpoint poses match.

## World-space animation reduction (optional)

In **Animation optimization / Advanced**, choose **Reduction method / World-space bound**. The existing Simple strength slider then adjusts **World-space tolerance**, the maximum vertex difference for fast animations. Local tracks remains the default. Zero performs exact key cleanup and proven quaternion representation changes.

Each animation gets a budget from its own peak skinned-vertex speed divided by mesh size. At Simple 100, the maximum is 1% of the widest bind-mesh dimension. Animations moving no faster than half a model size per second use one quarter; the budget increases linearly to the maximum at 6.5 model sizes per second. Strength scales it quadratically, as the existing slider does. No animation or bone names determine these limits. Advanced can set the maximum directly. Pose/subtree caches reuse immutable samples and invalidate edited descendants. A conservative constant-rotation/linear-translation speed certificate may establish the unchanged quarter-budget without visiting every frame; all approximate deletion/refit displacement checks still use 1 ms samples. The certificate and timing evidence are documented in the verification log.

The mode first reuses exact interior-key cleanup and unused-local-key removal on unexcluded node transforms. Frame-zero setup keys and wholly unassigned tracks retain that owner's exclusions. It can also drop a final key only when the preceding local hold is proven constant and keeps the final pose identical. This boundary deletion is separate from the interior-key owners.

Approximate changes run parents first. Every affected vertex, including blended and descendant influences, is compared against the immutable model at the start of this stage. Sampling covers every integer millisecond between retained keys, with extra quarter probes for one-millisecond fitting spans. Earlier accepted deletions on the chain share the same budget. Sequence start/end poses remain exact. Lowering strength rebuilds from the same approved input.

The existing 10% component/turn protection still guards an excursion if the mesh budget could flatten it: translation range is in model units; rotation and scaling use existing bind-pose reach to estimate excursion size. Larger excursions use the direct posed-mesh limit. Reach chooses the small-motion guard; it does not accept a deletion. **Local tracks** retains its full original component/reach rules and numerical tolerances.

A quaternion cubic whose controls all equal their own keys has identical inner/outer slerps under squad and can be represented as linear without changing its curve. Vector Hermite controls do not share this identity. Other local cubic transforms may be refitted as linear through adaptive sampling and the same world/motion checks, only when the complete track is smaller and every animation it touches passes. Unassigned setup records or overlapping domains block a whole-track refit.

This mode adds no checker fixes and does not execute Remaining cubic redundancy. Redundant-key cleanup and spline-notice repairs retain their approval and signature checks. Rescan uses current data; stale plans cannot write over a world-mode result. Geoset exclusions protect shared dependencies.

The guarantee is sampled skin displacement against this stage's input, not continuous-time, velocity, camera appearance or Warcraft III acceptance. Global tracks and skin influenced by global, non-unit rotation or camera-facing/anchored transforms are not approximately reduced. Other approved stages can change geometry or motion; a later optimization uses its newly approved input as baseline. Inspect playback before approving. Private teaching-case measurements and the saving shortfall versus its manual reference are in the [verification log](OPTIMIZEXL_VERIFICATION.md).

## Saving into the open file

**Save**, at the top right, is the editor's only save action. It is enabled once a change has been approved and not yet saved. It writes the approved result into the model you are working on, as one undoable **OptimizeXL** step in the main editor followed by its normal save (same file, same MDL or MDX format). The current unapproved preview is never included.

The first save in an OptimizeXL session asks whether to keep a backup: **Back up, then save** first copies the file as it is on disk to `Name_backup.mdx` beside it (`Name_backup_2.mdx` and so on if taken; existing files are never overwritten), **Save without backup** saves straight away. Later saves in the same session save directly. No other files are written. A model that was never saved asks where to save, like the main editor.

**Commit**, next to Save, applies the approved result to the open model as the same undoable **OptimizeXL** step and returns to the editor without saving the file; save it from the editor when you are ready.

Saving leaves the current stage and proposal open so you can keep reviewing. Closing OptimizeXL with approved changes that are not saved asks whether to save or commit them first.

## Current scope and evidence boundaries

- Editable Classic/SD MDL/MDX version 800. HD skin/bind-pose data, unknown sections and trailing data are not supported by this optimizer.
- Hidden-in-one-animation geometry is retained. This version removes unreferenced data; it does not guess that occluded surfaces can never become visible in another animation.
- Invalid animation bounds are rebuilt from authored key times and regular sampled poses. This changes extent metadata, preserving meshes, animation keys and visibility; it is not an analytic bound for every possible continuous pose or independent global-sequence phase.
- Geoset sequence-extent tables with too few or too many records use the same bounds repair. It reconstructs the entire mismatched table from current animated geometry, retaining sequence indices and leaving matched tables unchanged. Unskinned bones can still drive descendants or reference geoset animations; their checker warning explains the need to inspect those dependencies before removing or changing the bone.
- The default Local tracks animation reduction compares local transform samples against the stage baseline, with turns and scaling bounded by each part's bind-pose reach. Errors from several parts in one chain can still add up, so it is not a proof of a world-space error bound at every possible instant. Skinning, effects and all intended animations still need visual review.
- Nuclear ranks collapses using surface, normal and every UV channel's error rather than edge length. It retains original vertex positions, normals, UVs and bone bindings; it does not reposition vertices. UV seams/open boundaries, sharp edges and skinning boundaries constrain reduction when enabled. It can stop before the requested target and does not promise invisible polygon reduction.
- Nuclear's Advanced **Shape/texture error (%)** is the simplifier's combined relative error budget, including weighted UV and normal differences. It is not a maximum movement distance or a percentage of pixels changed. Simple strength gradually increases this budget from 0 to 20% while reducing the requested target, keeping all protections enabled. The target is a request, not a guaranteed output count.
- The bundled checker is pinned to mdx-m3-viewer 5.12.0 and runs locally without uploading a model. A clean check is not Hive moderation approval or proof of Warcraft runtime behavior.
- Missing local opening keys are proposed using Hive's interpolated-channel rule. The repair holds the first authored value until the original first key, matching native playback. For cubic tracks it neutralizes that key's previously unused incoming control; its outgoing control and remaining keys stay intact. Step/global/constant channels and overlapping animation intervals are excluded. This repair does not delete unused local keys outside animations.
- Insanity Fixer separately offers removal of local keys outside every animation, matching Hive's unused-key finding. Setup keys at frame zero and global tracks are retained. A track must retain in-animation keys; wholly unassigned tracks need a separate static/base-value decision. Select these repairs with the opening-key repair to clear all four findings in the supplied Flail02 models.
- Redundant-key cleanup handles Hive's exact/roughly-equal interior keys across supported local and global scalar/vector/quaternion channels. Each proposal owns one track/domain and rechecks neighbors after removal, comparing the resulting curve against the original span. Non-unit rotation data elsewhere in the track does not block an otherwise supported span. Meaningful spline excursions, invalid affected controls and overlapping local intervals remain inspectable. This is a separate approved checker cleanup; existing animation-reduction tolerances and outputs are unchanged. First/last keys remain, and the per-component sampled change must stay below Hive's .001 similarity threshold.
- When equal-valued cubic keys carry meaningful motion, Insanity Fixer can separately offer **preserve curve and clear spline notices** after existing supported key-level repairs on that track have been approved. It resamples only the affected local bone/helper TRS spans using native interpolation and retains the original interpolation type, exterior handles, outer anchor values and unrelated records. Quarter-millisecond curve comparisons must stay below .001 per component, and the affected domains must have no remaining value-redundancy notices. Global, overlapping, invalid or excessively sharp spans remain inspectable. This is an explicit representation repair and can increase file size; it does not guarantee an analytic continuous, world-space or visual error bound.
- Irregularities Fixer also checks additive glow geometry against overlapping solid geometry using exactly matching skin-bone sets. It requires co-visibility in at least two animations and evidence that every associated solid component is hidden throughout the suspect animation. The proposed fix changes only the glow's local visibility there. Ordinary materials, distant geometry and globally animated effect visibility do not trigger this rule; overlapping sequence intervals remain inspection-only. This rule covers attached additive geosets, not all possible particle or ribbon relationships.

## Research and preset provenance

[Hive: Collision Shapes, How to Make Your Model Selectable](https://www.hiveworkshop.com/threads/collision-shapes-how-to-make-your-model-selectable.156930/) supplies the standard radius-40 sphere at Z=40 and the tall-unit example with radius-60 spheres and an upper sphere at Z=140. Small/Large are scaled starting choices; Mounted rider uses the three radius-55 spheres from the reviewed Khorne rider. These are editable starting presets, not statistical averages of Hive models.

The current **Standard unit** preset replaces that original radius-40 starting sphere with the supplied Footman's two authored radius-38.076 spheres, centered at (5.25745, 0, 63.221) and (3.23942, 0, 22.8474). The Original and Unoptimized Footman files contain identical collision geometry. The preset uses the exact float values from those files.

[Hive: Fixing Faulty Death / Decay Animations](https://www.hiveworkshop.com/threads/fixing-faulty-death-decay-animations.40794/) and [modelling questions and conventions](https://www.hiveworkshop.com/threads/modelling-getting-facts-straight-and-questions.271524/) inform the visibility and continuity proposals. [Blizzard Warcraft III Art Tools documentation hosted by XGM](https://xgm.guru/files/100/344093/comments/545702/Warcraft_III_Art_Tools_Documentation%5Ben%5D.pdf) describes loop endpoints, Ready/Attack/Death pose relationships and the death/decay sequence. Those conventions are prompts for review, not grounds for silently replacing artistic choices.

The [Hive model checker](https://viewer.hiveworkshop.com/check/) uses the [mdx-m3-viewer project](https://github.com/flowtsohg/mdx-m3-viewer). Its unmodified official npm distribution and MIT license are bundled under `public/vendor/` and copied to `dist/vendor/`.

Nuclear uses [`meshoptimizer` 1.3.0's `simplifyWithAttributes`](https://github.com/zeux/meshoptimizer/tree/master/js), with normals weighted at 1 and UV coordinates at 2, `RegularizeLight`, explicit bone/sharp-edge locks, and `LockBorder` when seam protection is enabled. Disabling seam protection permits topology changes across attribute discontinuities; it still includes UV and normal error. The complete MIT license and pinned package provenance ship with the unmodified module in `src/vendor/meshoptimizer-1.3.0/`.
